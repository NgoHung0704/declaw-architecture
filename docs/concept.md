# Atlas design

The overview is a top-down map of responsibilities. Functional landmarks carry the meaning: Brain's neuron connections, Memory's cabinet and vault lock, Tools' wrench and screwdriver, Documents' sheets and chunking station, Sanitizer's shield and filter, Approval's checkpoint, Workspace's folder, Storage's SQL cylinder and vector nodes, Ollama's model chip, Plugins' connector, Audit's event ledger and the CLI terminal.

The placement follows three axes. The main request crosses from CLI at the far left to the central Brain, then Tools and Workspace at the right. Memory and model inference support this layer from above. Documents, adjacent Storage and Plugins occupy the lower area, while Audit sits at the observation edge. Approval is above execution and Sanitizer is close to both Tools and the model service. Brain is centred exactly in the map; Brain and Documents receive larger parcels to establish the visual hierarchy. Sizes describe emphasis and room for explanation, not CPU, memory or runtime importance scores.

The visual hierarchy is district → source symbol → relation. A district opens directly into its graph through a camera transition and crossfade at the district's map position. Functions have left IN and right OUT ports; district-wide input and output bands explain the overall contract. Selected connections fit both endpoint cards and highlight only the relevant relationship. The inspector provides full explanations and pinned source links when map labels are abbreviated.

District routes are curated relationships. Calls point to the callee; awaited results return to the caller. Other patterns identify data/dependencies, conditional branches and construction/registration. Overview ports use the appropriate side of each parcel and spread multiple connections across that side, reducing detours around the central path. Internal symbol cards keep left IN and right OUT ports. All routes avoid node interiors. Crossings and shared routes can occur; selection isolates each relation. This is not a literal network deployment, circuit or runtime trace.

Both map levels support dragging, cursor-anchored wheel zoom, pinch zoom, fit and keyboard navigation. Transitions start from the visible camera pose and can be cancelled by gestures or replaced by a new district selection. Narrow panels start closer, with the complete scene always available through Fit. Node selection zooms closer, while full contracts remain accessible through the inspector.

The journey footer is part of the map frame and reserves its own space. It never floats over the data area. Map badges identify scenario order, including repeated visits to a district; only matching architecture relations are highlighted. The inspector tracks the active district. Playback can be collapsed, stepped, paused, reset or cleared.

Fullscreen gives the map the entire workspace and collapses the inspector. A full-window fallback serves embedded browsers that deny native fullscreen. On short screens the journey starts compact and the district directory yields its space to the canvas. An overview minimap supports orientation while zoomed in. The inspector can be reopened in fullscreen and becomes a drawer at narrow widths.

The source model remains deliberately separate from the renderer. Architecture descriptions and internal references are tied to DeClaw revision `2f37214e73cbbdadc8d037ce78d6c0e81a73a1ed`. All content is curated; changes in DeClaw require updating and verifying the model.
